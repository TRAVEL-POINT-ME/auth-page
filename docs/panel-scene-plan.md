## Архитектура

**Вся вёрстка — новая, с нуля по текущим фреймам Figma.** Форма поиска в этой итерации

восстанавливаем — размеры, инсеты и состояния чипов снимаем заново через

Переиспользуем из снесённого демо только **организацию и планировщик** — это машинерия,

## Токены движения

`--ease-out` в `tokens.css` (`cubic-bezier(0, 0, 0.2, 1)`) **не трогаем** — на нём висят
hover/focus всей auth-колонки. Новые кривые живут в `motion.ts` и пишутся как CSS-переменные
на корень панели через `motionVars(rate)` (JS владеет числами, CSS их читает — тайминги
не могут разъехаться):

```ts
export const EASE = {
  out:  'cubic-bezier(0.23, 1, 0.32, 1)',      // сильный ease-out: входы и выходы
  move: 'cubic-bezier(0.77, 0, 0.175, 1)',     // сильный ease-in-out: сдвиг стека, пилюля
  map:  'cubic-bezier(0.32, 0.72, 0, 1)',      // iOS-кривая (Ionic): оседание карты
} as const;
```

Пружина пинов не требует библиотеки: перелёт запечён в keyframes, кривая обычный `EASE.out`.

Разные длительности у opacity (500) и scale (1100) у карты — намеренно: проявление
успевает закончиться, пока масштаб ещё оседает. Это и даёт ощущение «долетели и встали».

**Длительности > 300ms здесь легальны**: скилл `/animate` явно выводит
marketing/explanatory из-под лимита. Микро-биты внутри формы (нажатие, выбор чипа)
остаются в 140–190ms.

### Пины — Pop in + Ripple

6 пинов: три из Figma 1-в-1 (454/189 32px, 94/395 24px, 529/638 28px) + три поменьше
(18–22px) в пустых зонах карты. Позиции — в % от `.mapBox`.

Одноразовая непрерываемая анимация → **CSS keyframes** (скилл запрещает keyframes только
для часто перезапускаемых элементов; заодно они идут мимо main thread):

```css
@keyframes pin-drop {
  0%   { opacity: 0; transform: translateY(-22px) scale(0.7); }
  55%  { opacity: 1; }
  70%  { transform: translateY(0) scale(1.06, 0.92); }  /* squash об землю */
  85%  { transform: translateY(0) scale(0.98, 1.03); }  /* stretch-отскок */
  100% { opacity: 1; transform: translateY(0) scale(1); }
}
```

`transform-origin: 50% 100%` — остриё пина. Сплющивание происходит в точке касания,
а не в центре иконки.

Ripple — псевдоэлемент `::after`, кольцо `scale(0.3)→scale(2.4)`, `opacity .5→0`, 700ms
`ease-out`, `animation-delay` = 70% длительности дропа, чтобы волна пошла ровно в момент удара.

### Стек пушей — новый сверху, толкает вниз

Порядок прилёта (по таймстемпам Figma, снизу — самое старое):
**Pet amenities (12m) → Round-trip transfer → Hotel confirmation.**

Каждая карточка — два вложенных элемента, чтобы два transform'а не дрались:

- **`.slot`** (внешний) владеет позицией в стеке: `translateY(0 | 76px | 152px)`.
  `transition: transform 360ms EASE.move`. Двигается, когда сверху приезжает новая.
- **`.card`** (внутренний) владеет входом: `opacity 0→1`, `translateY(-14px) scale(0.96)` → `none`.
  `transition` 300ms `EASE.out`.

Сдвиг и вход идут одновременно — новая карточка физически расталкивает стек.
Значения `translateY` ставятся **напрямую в `element.style.transform`**, не через CSS-переменную
на родителе (переменная на родителе форсит пересчёт стилей у всех детей).

Оба движения — transitions, а не keyframes: при быстром перезапуске сцены они
ретаргетятся с текущей позиции вместо рестарта с нуля.

## Переключатель сцен

В коде его нет вообще — строим с нуля. Два настоящих `<button type="button" aria-pressed>`.

Белая пилюля должна ездить между пунктами, но у пунктов разная ширина, а анимировать
`width` — это layout thrashing. Берём **clip-path-технику для табов**: ряд дублируется,
копия стилизуется как активная (белая пилюля + тень + иконка), и копия клипается
`clip-path: inset(...)` по прямоугольнику активного пункта. Анимируется только `clip-path`
(санкционированное четвёртое свойство), цвет текста и иконки переходят идеально —
таймингом отдельных цветовых переходов такого не добиться.

Чтобы геометрия обеих копий совпадала до пикселя, **оба пункта в обеих копиях резервируют
слот под иконку**; в базовой копии иконки `opacity: 0`, в клипаемой — видимые.

Длительность 250ms, `EASE.move` (индикатор таба — движение по экрану, не вход).

Клик перезапускает выбранную сцену с начала (`timeline.reset()` + `playScene(n)`).
Сцена 2 — пустой слот с тем же кроссфейдом `[data-scene] / .is-active`.

## Доступность

- Сама сцена — `aria-hidden="true"`, внутри ничего фокусируемого. Декорация.
- Пилюли переключателя — **вне** aria-hidden-поддерева: это настоящие интерактивные кнопки.
- `prefers-reduced-motion` — два слоя, как в снесённом коде:
  1. JS-выход: `usePanelScene` рисует конечный кадр целиком (`renderRestingFrame`) и
     не проигрывает последовательность вообще.
  2. CSS-одеяло, ограниченное `[data-panel]`: длительности в `0.01ms`, но не `none` —
     чтобы смена состояния по клику на пилюлю всё-таки доезжала, а не выглядела сломанной.
- Гейты проигрывания (переносятся из `useDemo.ts`): IntersectionObserver < 0.4,
  `visibilitychange`, и **жёсткий стоп** при фокусе в поле формы входа — сцена
  не должна дёргаться сбоку, пока человек вводит почту.

**Три решения, принятые уже по ходу — не переигрывать без причины:**

1. **Карта: flat-field нормализация + `mix-blend-mode: multiply`.** Требование —
   фон под картой должен быть неотличим от фона под формой поиска, иначе переход
   палится. Экспорт Figma этого не давал: его «фон» не белый и неравномерный —
   центр `(250,250,254)`, углы `(245,244,248)`. Под multiply это темнило панель
   на 5–10 уровней относительно `#f2f2f5`.
   Гистограмма показала чистое разделение: штрихи 184–239 (≈4.8% пикселей),
   фон 240–255 (95%). Кривой их не развести — либо фон остаётся тёмным, либо
   выгорают слабые штрихи. Поэтому **flat-field**: поле фона оценивается сильным
   размытием и картинка делится на него, после чего фон садится в 255 везде,
   а контраст штрихов сохраняется по построению:
   ```
   ffmpeg -i map-export.png -filter_complex \
     "[0:v]format=gbrp,split[a][b];[b]boxblur=luma_radius=80:luma_power=2[bg];\
      [a][bg]blend=all_mode=divide,format=rgb24" map-flat.png
   ffmpeg -i map-flat.png -vf "colorlevels=rimax=0.988:gimax=0.988:bimax=0.988" map-final.png
   cwebp -lossless -z 9 map-final.png -o panel-map.webp
   ```
   Проверено в браузере: фон исходника `(255,255,255)`, после multiply над панелью —
   `(242,242,245)`, то есть ровно `--c-panel`. Фон при появлении карты не меняется.
   **webp обязательно lossless** (187 КБ): при `-q 95` (48 КБ) чистый белый разрушается —
   ровно 255 остаётся у 0.16% пикселей вместо 92%, фон уезжает в 252–254 и эффект теряется.
   Любая другая светлая карта наследует ту же обработку — нужно только прогнать её
   через те же три команды.

   ⚠️ **Текущая карта — не финальная, автор её ещё поменяет.** Ценность здесь в
   основе, а не в конкретном файле: точка подмены — один импорт в
   `PresentationPanel.tsx`, обработка (multiply + маска + вылет) живёт в CSS. Новую
   карту прогнать через три команды выше, иначе фон снова разъедется с `--c-panel`.

   *Тупики, чтобы не проходить их заново:* `rawImages` содержат два промежуточных слоя
   пайплайна, а не картинку — `raw1` это матовая заготовка (белые дороги на `#00FF00`),
   `raw2` — зелёные штрихи на прозрачном фоне. У `raw2` действительно честная альфа
   (93% прозрачных пикселей), но штрихи в нём светло-зелёные `(218,247,247)`: в градациях
   серого это 241, то есть на панели они просто исчезнут. `colorkey` на `raw1` оставляет
   25% зелёной бахромы на антиалиасинге. Работает только `export` + flat-field.
2. **Радиальная маска оставлена мягкой** (`#000 72% → transparent 100%`). Первая версия
   (`44% → 88%`) складывалась с затуханием, уже запечённым в экспорте, и вымывала дороги
   в ничто. Маска здесь — страховка для карт без собственного затухания, а не второй слой
   того же эффекта.
3. **Карта уходит в ультраширокий вылет, клип односторонний.** `.panel::after` —
   позиционированный псевдоэлемент, который уносит серый к краю вьюпорта, и он идёт
   в DOM после панели, то есть закрашивался **поверх** карты: справа оставалась плоская
   серая полоса. Лечение: `z-index: 1` на `.root`, ширина вылета считается как
   `--map-bleed: max(0px, (100vw - (var(--zone-w) + var(--panel-w))) / 2)`, и `.mapLayer`
   уезжает вправо ровно на неё. Не на `-100vw` — при таком вылете `object-fit: cover`
   зумит карту в несколько раз. Клип у `.root` сделан `clip-path: inset(0 calc(-1 *
   var(--map-bleed)) 0 0)`, а не `overflow: hidden`, потому что резать надо только слева
   (граница с белой зоной, куда не должна залезать увеличенная карта), а справа —
   пропускать.

4. **`.panelInner` удалён.** Сцена центрируется по всей высоте панели (`display: grid;
   place-items: center`), потому что Figma ставит оптический центр формы ровно в центр
   фрейма (452 из 903). Прежние асимметричные отступы 55/34 сдвигали её на 10px вниз.
   Отступы вернутся отдельно — под ряд пилюль внизу.

**Гейт видимости работает и это мешает скриншотам:** headless-вкладка превью всегда
репортит `document.visibilityState === 'hidden'`, поэтому секвенция там сразу встаёт на
паузу, а композитор отдаёт протухшие кадры. Для проверки в такой вкладке: нажать `restart`
в DEV-транспорте, а перед скриншотом форсить перерисовку
(`el.style.display='none'; void el.offsetHeight; el.style.display=''`).
В обычном браузере ничего этого не нужно — играет само.
